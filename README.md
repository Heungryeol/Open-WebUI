# Open-WebUI

Open WebUI 에 올려 쓰는 Function 코드 보관소.

## functions/pais_multi_agent_pipe.py

PAIS(VMware Private AI Services) 의 Agent 들을 Open WebUI 모델로 노출하는 Pipe.
Authentik OAuth2 password grant 로 토큰을 받는다.

### 적용

1. Open WebUI 관리자 → Functions → PAIS Multi Agent Pipe → 코드를 이 파일로 바꾸고 저장.
2. **Valves 에서 `Oidc Client Id` 와 `Oidc Password` 를 넣는다.** 이 저장소는 공개라 두 값을 코드에 두지 않는다.
   코드를 바꿔 저장하면 Valves 가 빈 기본값으로 돌아갈 수 있다(2026-10-22, Valve 를 더한 판에서 실제로 비워짐 →
   `invalid_client`). **코드를 바꾼 뒤에는 항상 Valves 의 Client Id·Password 를 다시 확인한다.**

### 대화 이력 다듬기 (2026-10-22 추가)

에이전트가 앞 답의 KB 글을 베껴 도구 없이 답하던 문제(BRCM-MCP 쇼케이스 리허설)를 막는다.

| Valve | 기본 | 뜻 |
|---|---|---|
| `HISTORY_MODE` | `strip_kb` | `full` 이력 그대로 / `strip_kb` KB 가 든 이전 답은 짧은 표시로 / `user_only` 이전 답 모두 짧은 표시로 / `last_only` 마지막 질문만 |
| `MAX_HISTORY_TURNS` | 6 | 마지막 질문 앞에 남길 이전 대화 쌍 수 |
| `KEEP_ANSWER_CHARS` | 600 | KB 가 아닌 이전 답을 남길 글자 수 |
| `STRIP_TABLES` | 켬 | (10-22 추가) `strip_kb` 에서 이전 답의 마크다운 표는 머리 줄만 남기고 데이터 행을 "(표 N행 생략 — 첫 열: a, b, c …; 지금 값은 도구로 다시 조회)" 한 줄로(첫 열 값 최대 8개). 표 밖 문장은 남는다 |
| `SAME_QUESTION_HINT` | 켬 | (10-22 추가) 같은 채팅에서 이전과 같은 질문이면 "(같은 질문: 값이 바뀌었을 수 있으니 도구를 다시 호출)" 한 줄을 붙임. 공백·문장부호·대소문자·Q 번호·끝의 "요/줘/주세요" 만 무시하고 완전히 같을 때만, 그 질문의 답이 도구 답(표·KB·도구 이름)이었을 때만. 인사·감사·자기소개와 "나머지 보여줘" 류는 제외 |
| `TOOL_HINT` | 켬 | (10-23 추가) 해결·조치·방법("방법론" 제외)·절차·"어떻게 해/고치"·how to/fix 질문, 또는 영어 오류 문구(라틴 낱말 4개 이상 + error·fail·unable·cannot·no more·denied·timeout·not responding·invalid·refused 같은 오류 낱말)가 든 질문에 "(이 질문은 도구로 답함: 오류·해결은 KB 검색, 로그 줄은 로그 도구, 알림은 Operations. 앞 답이나 기억으로 KB 를 쓰지 않음)" 한 줄. 영어 오류 문구라도 로그 검색 낱말(줄·로그·찾아·검색·들어간)이 있으면 붙이지 않음(해결 낱말이 있으면 붙임). 인사·잡담, "나머지 보여줘" 류, 다른 힌트가 붙는 질문에는 붙이지 않음 |
| `FOLLOWUP_HINT` | 켬 | 주제 없는 짧은 후속 질문("잠금 해제 방법")에 앞 질문을 붙여 넘김 |
| `FOLLOWUP_MAX_CHARS` | 25 | 후속 질문으로 볼 최대 글자 수 |
| `FORCE_TOOL_CHOICE` | 끔 | (실험) `tool_choice=required`. PAIS 가 받는지 쇼 뒤에 시험 |

"나머지 보여줘" 류("나머지도 보여줘", "나머지 알려줘", "다음 페이지", "계속", "더 보여주세요")는 바로 앞 답의 도구로 이어 보기를 부르라는 한 줄을 붙여 넘긴다. 화면의 질문은 바뀌지 않는다.

같은 채팅에서 앞 표를 그대로 반복하거나 없는 행을 지어 붙이던 문제(BRCM-MCP #57 3절, F2 Q4)는 위 두 Valve 로 막는다.
앞 표의 값(이름 첫 열 몇 개 말고)이 모델에게 보이지 않으므로 표 값을 다시 물으면 도구를 불러야 한다. 두 Valve 를 끄면 10-22 이전 동작과 같다.

질문 전체를 백틱(`…`, ```…```)이나 따옴표로 감싸 보내면, 안이 질문 꼴(방법·해결·알려·보여·찾아·?)일 때만 껍데기를 벗겨 넘긴다(10-23, 백틱으로 감싼 오류 문장에 도구 호출 없이 지어낸 KB 답이 나왔다). 따옴표만 친 로그 문구(`"Update virtual NIC"`)와 문장 안 일부만 따옴표인 것은 그대로다. 펜스 첫 줄은 bash·sh·python·json·yaml·text·console·powershell 같은 언어 이름일 때만 뺀다. 잡담 판정은 메시지 전체가 짧은 인사·감사·자기소개일 때만이다 — "안녕하세요, … 해결 방법" 은 인사를 떼고 판단하고, "감사 로그" 는 잡담이 아니다. 잡담에는 어떤 힌트도 붙지 않는다.

### Open WebUI 작업(제목·후속 질문 칩)은 파이프가 직접 답한다 (2026-10-23, BRCM-MCP #64)

Open WebUI 는 답이 끝나면 제목·후속 질문 칩·태그를 만들려고 **작업 모델**을 한 번 더 부른다. 작업 모델을 따로
정하지 않으면 지금 채팅의 모델, 곧 이 파이프(→ PAIS 에이전트)가 불려서, 아무도 치지 않은 문장으로 도구가
불렸다("현재 발생 중인 주요 장애 …", 159 10-23). 칩도 서버가 준 "이어서 물어볼 만한 것" 과 달랐다.

- Valve `LOCAL_TASKS`(기본 켬): 작업 요청은 PAIS 를 부르지 않고 파이프가 답한다.
  - 후속 질문 칩 = 마지막 답의 `이어서 물어볼 만한 것:` 아래 `- ` 줄 **그대로**(최대 `FOLLOWUP_MAX_CHIPS`, 기본 5).
    그 목록이 비어 있고 `관련:` 목록만 있으면 그것을 쓴다.
  - 답에 `이어서 보려면 '나머지 보여줘'` 또는 `… '나머지 보여줘' 로` 가 있으면 `나머지 보여줘` 를 맨 앞에.
    `문서의 끝입니다.` 로 끝난 답에는 `나머지 보여줘` 칩을 두지 않는다. 목록이 없는 답은 칩 없음.
  - 제목 = 첫 질문(40자까지). 태그·검색어·이모지·자동완성은 빈 값.
- Open WebUI 설정(관리자 패널 → 설정 → 인터페이스):
  - **후속 질문 생성(Follow Up Generation) 켜기.**
  - **작업 모델(Task Model, 외부)은 비워 두거나 이 파이프 모델로.** 다른 모델을 고르면 파이프를 거치지 않으므로,
    그때는 BRCM-MCP #64 의 Follow Up Generation Prompt 를 붙여 넣는다.
  - 제목 생성·태그 생성은 켜 두어도 된다(파이프가 PAIS 없이 답함).
